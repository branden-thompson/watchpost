## The four that are ruled already, and only need the row written

### `Effect.Duck` and `Effect.Restore` — writer is the DIRECTOR

Their own declaration says so — `platform/lineup/director.go:159-163`:

> *"the bed is a selectable resource rather than a queue, and **the Director gains it with the
> main-track absorb (T3.2)**."*

and the end state was ruled at 0.14.0 — `director-build-log.md:1086`:

> *"**The Director owns all ducking** — the arbiter stops dipping entirely.  **Rejected FOR NOW, and it
> is the end state.** … It arrives when everything reads through the Director (T3.2+)."*

**What that implies for the instrument.**  The duck becomes a decision of a PURE function, so it is
testable as data — which is the whole reason 0.14.0 wanted the decision half inside the Director's step.
The two questions become one property over `Director.Step`:

- a takeover admitted **while the bed is live** emits `Duck`;
- a takeover admitted **while the main track is what is playing** emits **nothing**;
- and the pair is closed: every `Duck` is followed by exactly one `Restore`.

**A mutant that inverts either condition is caught by a pure test with no audio device**, which is the
thing P3 could not do.

### `Power.OffAir` — writer is MASTERCONTROL

`role-model.md:91-92`: *"it declares ON AIR or STANDBY, and **everyone complies, the Director
included**."*  **FR-5.4** requires the operator's named control, and says it *"is a requirement rather
than a mock detail"*.

**This row IS RS-3 and F-72.**  The swap gate reads the Director's real power and nothing can produce
the state that clears it.  **The instrument that follows:** the control moves the Director's power (not
a UI flag, FR-5.1), STANDBY holds the rail too (NFR-7), and a paused main track is a **different**
condition (FR-5.6).

### `Origin.FromOperator` — writer is the OPERATOR, through the Producer

`director-requirements.md:41` (DR-4): the **Operator proposes**; origin is set at proposal.  The HUM
LEAD's ruling stands beside it: **a live card's origin never changes** — *"We can make new cards, or use
a card to make a copy … but while it's alive its origin should not change."*

**The instrument:** a card the operator placed carries `FromOperator` from proposal, and **a mutant that
rewrites an origin after admission is caught**.  That mutant does not exist today.

### `State.Proposed` — a false positive, and the ledger row says so

Nothing names it because it is the **zero value**: `Card{…}` is born PROPOSED and cannot be born
anywhere else.  That is deliberate design, not an unwired member.  **The honest disposition is a ledger
row, not code** — and writing it is what stops the next person "fixing" it.

## The two that were genuinely open

### ~~`State.Refused` — does a refused proposal become visible, or does the state retire?~~  RULED D-35: it becomes visible, in a capped discard pile the Director writes.

`Propose()` returns an **error** rather than a Refused card, so nothing ever reaches the state.  Its own
comment says *"REFUSED, DONE and DISCARDED lead nowhere: a card that could be revived is a card that can
be read twice."*

Two dispositions, and it is a product call:

| | What it means |
|---|---|
| **Give it a writer at P4** | the operator sees that a card was refused and why, rather than it never appearing.  A visible refusal is a station that explains itself |
| **Retire it** | AP-DEAD-01's own rule — *a slot nobody proposes is dead code* — applied to a state.  `BurstHead` and `DivertNotice` were retired for exactly this |

### `narrationClass.narrateRotation` — STILL OPEN, and D-36 is what makes it decidable

**Nothing reads it.**  The Reader writes it and no code anywhere treats the programme differently for
carrying it.  The arbiter's comparisons are `job.class > on.class` — variable against variable — so the
constant is never named.

**This is P3's first blocker as a static fact, and it was visible before a line was written.**

Two dispositions, and they are the same fork as F-73:

| | What it means |
|---|---|
| **Give it a reader** | something must treat the programme specially — at minimum, *do not take the duck for it*.  That reader is the give-way decision, which the Director gains with `Duck`/`Restore` above |
| **Retire the class** | the header three lines above it already says *"the broadcast itself (relay or synth) is not a narration: it is what gets ducked."*  If the programme is not a narration, it does not belong on the narration ladder at all |

**These two rows are one decision.**  Giving the Director `Duck`/`Restore` and giving `narrateRotation`
a reader are the same work seen from two ends; retiring the class and leaving the give-way to the engine
is the other answer.

## `Band.CloseBand` — benign, and worth a row so it stays that way

The planner writes it in four places and the ladder walk compares **rung to rung**, never against the
constant.  That is a real read the tool cannot see through a variable, and the disposition is a ledger
row noting the shape — a table-walk consumption — so the next unwired band is judged against it rather
than from scratch.
