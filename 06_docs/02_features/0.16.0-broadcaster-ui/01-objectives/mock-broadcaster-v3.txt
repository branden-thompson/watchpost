0.16.0 — BROADCASTER, v3 (HUM LEAD, 2026-09-12)

SUPERSEDES v2 BELOW THE STATION SECTION.  The console stops being a column of
cards and becomes what Observer already is: go-studs tables, the same labels, the
same prefix and alert tags, one shared pointer.

THE HUM LEAD'S OWN NOTES AND MOCK FOLLOW, VERBATIM.  This file is the reference
the layout tests read their numbers out of, so it is kept exactly as it was
given — a mock that has been "tidied" is no longer evidence of anything.

The GPS on the STATION line is a placeholder (F-66); real coordinates render only
on the operator's own screen.

Notes before you look at the mock:

- Tables should follow the same labelling / colorscheme / behavior approach as Observer
- Up Next and Alert are always present - if there are no active alerts taking over, then the box is simply empty
- Pointer state is shared across the two go-studs tables (Line-Up / Location Pool) just like it is in the Observer tables (Watchlist / Recent)
- Location Pool table should fill with our 25 location cap, and should function just like Observer's weather table - RATIONALE: gives the human operator some basic weather info to determin if they want to have that location priotized in the schedule linuep

- Our lineup expands from 10 -> 15.  If it's leveraging the same mechanism as Observer, then Observer's watchlist should also grow from 10 -> 15. It also has all the same prefix / alert tags as the Observer table - this is to ensure the experiences are more consistent and the user doesn't have to "relearn" what certain things mean in between experiences.

This should help harmonize some of the plumbing because now Observer and Broadcaster are actually *closer* in their presentation as a result.
