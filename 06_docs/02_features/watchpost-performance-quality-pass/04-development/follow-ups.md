Raised by HUM LEAD while Q5 was in build, from using `v0.9.7`. Not folded into the pass: each is a
behaviour the pass changed or exposed, and each gets its own DISCOVER before a fix.

| # | What HUM LEAD saw | Most likely cause (to confirm) | First move |
|---|---|---|---|
| F-1 | The RECENT / SEARCHED table "loads slower, and all at once": the empty state shows for a few seconds before the seeded rows appear. Actual performance is faster; it *feels* slower. | Confirmed: Q3's RECENT publish window (5 s) applied to the **seed** publish too, so the empty state held until the first window elapsed, and the launch burst then landed in 5 s steps. | **Fixed 2026-08-27 (HUM LEAD's UX UAT: "the early table flush with rehydration in the columns").** The publisher's first publish runs at once, and for the first 90 s the RECENT window is 250 ms (`recentLaunchWindow` / `recentLaunchPhase`), then 5 s. Pinned by `TestFirstPublishIsImmediateAndLaunchFillsProgressively`. Measured on a pty from spawn: the seeded rows ("Showing 1-…") on screen at **159 ms**, the empty state never shown, cells rehydrating under the loading shimmer as fetches land. Steady-state publishes unchanged (one per tier wave). |
| F-2 | Some locations "no longer default to a Nearest Relay" (Carlsbad, Vista, Lone Pine, Coachella, then Temecula, El Cajon, South Lake Tahoe, Los Angeles, Palomar Mountain). | **Root cause found 2026-08-27 (HUM LEAD): a two-press bug, not relay resolution.** `WATCHPOST_DEBUG_RADIO` showed every mount — plain-HTTP weatherUSA included — reaching `playing` within a second; the "works/doesn't" list alternated perfectly with the *parity of presses*. `[space]` stopped whenever the radio was already marked playing the *previous* location, so on a newly selected location the first press stopped the old stream (silence) and only the second tuned the new one. Not HTTP-vs-HTTPS, no proxy. | **Fixed:** `[space]` plays the focused location, and stops only when that location is already the one playing (`radioToggle`, `TestSpaceRetunesToTheFocusedLocationNotStop`). The Spanish broadcast at Coachella/Palomar (`WNG712`) is a separate language-preference request (§0.9), still open. `WATCHPOST_DEBUG_RADIO` and the per-location diagnostic (`TestLiveRelayDiagnoseLocation`) stay as tooling. |
