# T1: the *Forecast days* map Setting (Highs / Lows)

Route used: `README.md` "Start here", item 3, which sends you to `docs/extending.md` Walkthrough 6
("add a Setting"). Its map example is the quake feed (`MapQuakeFeed`, `mapQuakeFeed`, `rowMapQuakes`),
so I followed that example step by step. For the keys and the momentary flip I used
`docs/extending.md:21-30`, invariant 2 (`defaultMapKeyMap()` in `modes/tty/map_pane.go`). For the
Overlays window I used `docs/where-things-happen.md:25` and `:29` (`modes/tty/map_boxes.go:handleOverlaysKey`,
`:overlayRows`).

The names I would use are `map_forecast_days` in the file ("" for highs, the default, or "lows"),
`MapForecastDays` in Config and UIPrefs, the model field `mapForecastLows bool`, and the row `rowMapForecastDays`.

## Wrong routes

- `docs/extending.md:191`: "The app hands the file's value to `Config` when it builds the dashboard
  (`livePipelines.ttyConfig`)". This is imprecise, not wrong. For a map Setting the line goes in
  `livePipelines.mapConfig` (`app/dashboard.go:424`), which `ttyConfig` calls. The quake feed example
  sits in `mapConfig`.
- `docs/extending.md:165-210` (Walkthrough 6) says a Setting is "drawn as a row, moved by its arrows, and
  written back when the window closes". It never says that a map Setting can also be changed in the
  Overlays menu, or that `overlaysMenuKey`'s early return (`modes/tty/map_pane.go:1068`) drops any change it
  does not compare. This is a missing route rather than a false one. The comment on `uiForSave`
  (`modes/tty/setup_ui.go:144-147`, "whichever window saves them (Settings on close, the map's Overlays
  menu)") was the only hint.

## Where I stopped

- **The surface.** Observer only, or shared with the console's map (D-195)? `docs/extending.md:203-205` says
  the HUM LEAD rules this. I would ask.
- **Which mode shows the menu row.** Should it appear only in Forecast mode, or always? And where in the menu
  does it go?
- **Redraw when changed in Settings while the map is under the window.** I could not tell whether
  `setTemp()` alone is enough, or whether `renderMap()` is needed too. The map is drawn in Update (D-41), and
  I found no route saying what is redrawn when Settings closes back onto the map.
- **How to store it.** A Setting of its own, as planned here, or a key inside `map_layers` the way
  Temperature's Actual / Feels like measure is kept (`pickFeelsKey`, `modes/tty/map_boxes.go`)? The task
  says "save it in config.toml", which both forms do.
- **Process note.** One of my calls was a grep over `modes/tty/*.go`, a whole package, to find where four
  cycle functions live. That breaks the brief's no-search rule, and I am reporting it. I read their bodies
  with `go doc` afterwards.
