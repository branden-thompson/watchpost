The Broadcaster: the air and the deck

1. One deck, one air

06_docs/02_features/0.16.0-broadcaster-ui/03-architecture-design/as-built-air-and-deck.md

Both surfaces run through the SAME deck, on purpose (HUM LEAD, 2026-09-12): both do synth reads and relay streams, so two decks would be duplicated code and two things that could play at once. The Director arbitrates the rotation in BOTH modes; MasterControl gates the deck from the air.

4. The guard boundary — D-91

06_docs/02_features/0.16.0-broadcaster-ui/03-architecture-design/as-built-air-and-deck.md

The seams between a surface and app are every tty.Config func field and every tty.Radio method. The classification is a closed set, derived by reflection, ratcheting both ways (TestEverySurfaceSeamIsClassifiedForTheAir, app/air_boundary_test.go), so the test, not this page, holds the count in each class.
